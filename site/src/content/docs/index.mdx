## Why Griff

Most engines make you stop the game to change it, lose your changes when play mode ends, and break undo in creative ways. Griff is built around a few promises.

<div class="features features-wide">
	<Feature title="The game keeps running while you change it" shot={editorScript} alt="Griff's script editor with the Arcade template's Ship script open, and the component it makes beside the code.">
		Save a C# script and every instance of it is swapped in the running game within a moment. Public properties carry over and the game doesn't restart; a compile error leaves the last good version running and points at the line.
	</Feature>
	<Feature title="Levels painted in the Scene view" shot={editorTilemap} alt="Painting the Isometric template's courtyard: the tile palette, brush, rectangle and fill tools over the Scene view.">
		Tilemaps square, isometric or hex, in layers, with autotiles and slopes, painted with a brush, rectangles and fills. Prefabs, sprites drawn in the Sprite Painter and sounds made in the Sound Maker, all without leaving the editor.
	</Feature>
</div>

<div class="features">
	<Feature title="Rewind, breakpoints and stepping">
		Griff keeps the last 20 seconds of play: drag back to just before the bug, tweak something and resume. Breakpoints cost nothing, a script that throws stops at the line that threw, and you step a line at a time into the next frame.
	</Feature>
	<Feature title="Undo covers everything, and play can't hurt your work">
		Every change goes through one undo history, even across a script reload. Play runs on a copy of the scene; Stop puts everything back, and Keep Play Changes copies the values you found while playing into your scene.
	</Feature>
	<Feature title="Build with an agent">
		While it's open, the editor serves the Model Context Protocol, so an agent like Claude Code can build games with it. Every command, component, window and panel is a tool, and anything added later shows up by itself.
	</Feature>
	<Feature title="The same game on every machine">
		The game moves in fixed steps whatever the screen's frame rate, and is drawn smoothly between them: smooth on a 144 Hz screen, and the same input gives the same result anywhere.
	</Feature>
	<Feature title="Multiplayer for every kind of game">
		Host or join over the local network or the internet, or run a dedicated server. Each player moves their own character at once, and Griff's components work for every player, from platformers to strategy.
	</Feature>
	<Feature title="One click to ship">
		Build Game makes a single `.exe` that carries everything, .NET included, so players install nothing. Build Small Game makes a 4 MB one for players who have the .NET Desktop Runtime.
	</Feature>
</div>

## Play the templates

Every template is a whole game, playable and audible from the first second, and every one is playable right here: click a card to open it and play in your browser. In Griff's editor you pick one in New Project and change it into yours, and Build for Web exports your own game the same way.

<Gallery />

Games start when you click them, so this page stays light, and sound starts with your first click or key. Network play isn't available on the web; each game's page says what it takes and how it plays. [All games](/games/)
